## 为什么要有RLHF（Reinforcement Learning from Human Feedback）？
*   **SFT的致命缺陷：** SFT只是“行为克隆”，教会了模型人类对话的**格式**和**语气**，但模型依然是一张没有底线的白纸。如果被问到危险问题，它会用标准的客服语气提供有害指南。
*   **RLHF的终极目标：** 大模型训练的第三阶段。为模型注入**人类的价值观和偏好**，教它明辨是非，使其符合**3H原则：** Helpful，Honest，Harmless。

## RLHF标准化训练过程

### 第一步：收集人类偏好数据（Human Preference Data）
1. **出题和作答：** 从题库取出一个Prompt，让刚刚完成的SFT的大模型生成两个不同的回答（回答A和回答B）。
2. **人类裁判打分：** 专业标注员根据安全性、逻辑性等标准，选出更符合人类价值观的一项。
3. **输出结果：** 形成一对明确的胜负数据：胜利者 ($y_w$) 和失败者 ($y_l$)。

### 第二步：训练奖励模型（Reward Model， RM）
**核心目的：** 训练一个“自动打分器”，代替人类在后续几万步的训练中给大模型打分。
*   **运行机制：** 考官模型（RM）接收一段对话，输出一个具体的标量分数（Scalar Reward）。回答越好，分数越高。
*   **核心数学表达(Pairwise Ranking Loss)：**
$$
L_{RM} = -\mathbb{E}_{(x, y_w, y_l) \sim D} [\log(\sigma(r_\theta(x, y_w) - r_\theta(x, y_l)))]
$$
这个公示的本质，就是强制拉大“好答案 ($y_w$)”与“坏答案 ($y_l$)”之间的分数差。分差拉得越大，考官的审美就越准。

### 第三步：PPO强化学习优化（Proximal Policy Optimization）
**核心目的：** 真正的训练阶段，利用RM考官的打分来重塑大模型的行为。
1. **实战演练：** 大模型（Actor）针对某个问题生成一段回答。
2. **毒打与奖励：** RM考官（Critic）立刻对该回答进行打分。
3. **权重更新：** 大模型根据得分，使用PPO强化学习算法，更新自己内部的FFN与Attention矩阵，朝着更容易拿高分的方向进化。
   
### 如何防止模型作弊
**痛点（Reward Hacking）：**

如果PPO阶段只让它追求高分，它很快就会发现RM的漏洞，最终变成不会正常回答的效果。 

### 解决方案：KL散度惩罚（KL Divergence）
给大模型带上“安全项圈”：在追求高分的同时，输出的内容概率分布**绝对不能偏离** 原本那个SFT模型太远。
最终优化目标公式为：
$$
\text{Maximize: } \mathbb{E} [r_\theta(x, y)] - \beta \mathbb{D}_{KL}(\pi_\phi^{\text{RL}} \parallel \pi^{\text{SFT}})
$$
左半部分 $\mathbb{E} [r_\theta(x, y)]$：拼命讨好考官，追求高分奖励。
 
右半部分 $\beta \mathbb{D}_{KL}(...)$：惩罚项。只要你说话不像正常人类（偏离了 SFT 基础模型），就狠狠扣分！

## PPO的替代方案DPO（Direct Preference Optimization，直接偏好优化）
*   **PPO的缺点**： 显卡里需要塞进四个大模型，可能会显存爆炸。
*   **DPO的诞生**： 斯坦福的科学家对着RLHF的底层数学公式推导，突然发现了一个惊天秘密：我们根本不需要单独训练一个“考官（Reward Model）”！


### DPO的核心逻辑：化繁为简
*   **RLHF（旧路线）：** 你想提高英语作文成绩。你先花钱请个外教（训练考官 RM），你写一篇作文，外教给你打个分，你根据分数慢慢瞎琢磨怎么改进（强化学习）。

*   **DPO（新路线）：** 直接给你发一本《满分作文与零分作文对比解析》（偏好数据）。你自己看着满分作文照猫画虎，看着零分作文引以为戒。不需要外教，直接自己悟！

DPO 通过数学推导证明了：大模型本身，就可以隐式地当作自己的“奖励模型（考官）”。

### DPO最关键的损失函数：
$$
L_{DPO} = -\mathbb{E}_{(x, y_w, y_l)} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)} \right) \right]
$$
1. $\pi_\theta$ (当前正在训练的模型) 和 $\pi_{ref}$ (冻结不动的参考模型，即 SFT 模型)。
2. $\log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}$：这是模型对好答案（胜利者 $y_w$）的概率变化。我们希望这个值越大越好（比起以前的自己，现在的我更愿意说好话）。
3. $\log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}$：这是模型对坏答案（失败者 $y_l$）的概率变化。我们希望这个值越小越好（比起以前的自己，现在的我极度抗拒说脏话）。
4. 中间一个减号，配合 Sigmoid 函数 $\sigma$，就是在做一件事：拼命拉大“好答案”和“坏答案”在你脑子里的概率差！
5. **$\beta$ 参数：** 它就是防止“学傻了”的项圈（隐式的 KL 惩罚）。控制你不要为了迎合偏好，偏离正常人说话的语气太远。

### DPO的极简流水线：
1. **准备数据：** 准备好 Prompt、$y_w$（好回答）、$y_l$（坏回答）。
2. **双模型载入：** 显存里只需要加载 2 个模型。一个是冻结不动的 Reference Model，一个是你要训练的 Policy Model。显存直接省了一半。
3. **前向传播计算：** 分别把好回答和坏回答扔进这两个模型，算出每个 Token 的生成概率。
4. **直接反向传播：** 套用上面那个优雅的公式，直接算 Loss，直接更新权重。没有 PPO 里的经验池，没有 Critic 网络，没有复杂的奖励计算。
   

## GRPO（Group Relative Policy Optimization，群组相对策略优化）

### GRPO的核心：同行衬托（Relative）
GRPO的核心思想：不预测基线，直接让模型**自己跟自己比**。

*   **PPO 的做法：** 学生做了一道题，Critic 老师掐指一算：“这题你正常发挥应该拿 80 分。” 结果你考了 90 分，比预期高（优势值为 +10），奖励你！
*   **GRPO 的做法：** 干掉 Critic 老师！遇到一道题，直接让学生用不同的思路做 $G$ 次（比如生成 8 个不同的回答）。然后把这 8 个回答拿去打分，算出一个平均分。谁比平均分高，谁就获得奖励；谁比平均分低，谁就挨打！

### GRPO的极简数学公式
在 GRPO 中，针对同一个用户提问 $x$，大模型生成了一组（Group）回答：$\{y_1, y_2, \dots, y_G\}$。

然后我们用规则或者 Reward Model 给它们打分，得到一组原始分数：$\{r_1, r_2, \dots, r_G\}$。

接下来，GRPO 用极简的**标准化（Z-score）**直接算出了优势值 $\hat{A}_i$：
$$
\hat{A}_i = \frac{r_i - \text{mean}(\mathbf{r})}{\text{std}(\mathbf{r})}
$$
(其中 $\text{mean}$ 是这组分数的平均值，$\text{std}$ 是标准差)算出这个优势值后，直接套用强化学习的截断目标公式去更新模型权重。

### GRPO造就了DeepSeek-R1
GRPO 之所以伟大，不仅仅因为它省掉了一个跟大模型一样大的 Critic 节点（显存直接暴降），更因为它完美契合了**“推理任务（Reasoning）”**的训练！

在做数学题或写代码时，答案是对是错非常明确（比如代码能不能跑通，数学结果是不是 42）。DeepSeek-R1-Zero 甚至连 Reward Model 都扔了，直接用一个**“规则校验器”**来打分：

1. 提问一道数学题。

2. GRPO 让模型生成 8 个解题过程。

3. 规则代码直接检查这 8 个答案，算对的给 1 分，算错的给 0 分，没有 <think> 标签的扣分。

4. 在这 8 个回答里算平均分，对的被强化，错的被弱化。

就是靠着 GRPO 这种极其高效、不需要 Critic、甚至不需要神经网路 Reward 的极致纯粹算法，模型在疯狂的试错中，自己“顿悟”出了反思、纠错和长链条推理能力。

### 总结GRPO
GRPO 就是砍掉了价值模型（Critic），依靠对同一问题采样多组回答并进行内部相对排名（标准化打分）的轻量级强化学习算法。它可以实现“强化学习降本增效”与“激发 LLM 推理潜能”。

## 🚀 大模型核心对齐算法对比：PPO vs DPO vs GRPO

| 对比维度 | PPO (近端策略优化) | DPO (直接偏好优化) | GRPO (群组相对策略优化) |
| :--- | :--- | :--- | :--- |
| **核心学习范式** | 在线强化学习 (Online RL) | 离线偏好学习 (Offline Learning) | 在线强化学习 (Online RL) |
| **大白话原理** | “考官打分，学生纠错” | “看满分和零分范文，直接照猫画虎” | “一题多解，同侪对比排座次” |
| **显存驻留模型数** | **4个** (Actor, Ref, RM, Critic) | **2个** (Actor, Ref) | **2个** (Actor, Ref) + 规则/奖励模型 |
| **Critic (价值模型)**| **必须有** (用来预测基准分，极其占显存) | 不需要 | **直接砍掉** (用生成群组的平均分代替基准) |
| **训练时需生成数据?**| 是 (模型实时生成回答，考官实时打分) | 否 (直接喂入人类提前标好的一对静态数据) | 是 (对同一问题实时生成 $G$ 个不同的回答) |
| **训练稳定性** | 💣 极低 (超参数极其敏感，容易 Loss 爆炸) | 🛡️ 极高 (转化为分类问题，和微调一样稳) | ⚠️ 中等 (去掉了 Critic 略微变稳，但仍是 RL) |
| **算力与显存开销** | 极高 (多模型流转 + 实时生成负担) | **极低** (无实时生成，普通算力即可驾驭) | 很高 (虽省了 Critic 显存，但多路采样极耗算力) |
| **能力天花板与探索** | 高 (能在打分机制下探索优秀的表达) | 容易触顶 (死死受限于提供的数据集最高水平)| **无限可能** (能在逻辑闭环中自我顿悟进化) |
| **最强适用场景** | 综合价值观对齐、早期通用大模型攻坚 | 基础聊天对齐、语气风格克隆、低成本对齐 | **数学、代码、长思维链 (CoT) 等硬核推理** |
| **代表落地大模型** | ChatGPT (GPT-4), Claude 3 | Llama 3 (主力对齐), Qwen 2 等绝大多数开源 | DeepSeek-R1 |
